# ReactiveBFM Deployment

This directory contains the deployment stack for ReactiveBFM on the Unitree G1
humanoid, migrated from the ScaleBridge Sim2Sim/Sim2Real framework
(`feat/reactivebfm-deployment` branch of the ScaleBFM deployment repository).

Two deployment paths are provided:

| Use case | Entry point | Description |
| --- | --- | --- |
| Online planning | `deploy/run_online_generation.py` | ReactiveBFM planner + ScaleBFM tracking policy in one real-time loop (MuJoCo or Unitree LCM) |
| Offline motion replay | `deploy/scalebridge/run.py` | Hydra-based loop that tracks a recorded `.npz` trajectory |

## Layout

```text
deploy/
├── run_online_generation.py   # online runner: planner <-> tracker closed loop
├── prompt_scheduler.py        # scripted/random/interactive prompt switching
├── tools/
│   └── play_rbfm_npz_mujoco.py  # qpos36 / session-recording playback in MuJoCo
├── assets/                    # deployment assets (a_pose_g1_36dim.json included)
├── scalebridge/               # tracking and robot-interface layer
│   ├── run.py                 # offline/Hydra policy loop
│   ├── agent/                 # BFM TensorRT agent + qpos task adapter
│   ├── env/                   # offline/online motion-tracking environments
│   ├── observation/           # observation terms
│   ├── simulator/             # MuJoCo and Unitree LCM backends
│   ├── utils/                 # config composition, logging, quaternion, overlay
│   ├── config/                # asset/agent/env/simulator configs
│   └── data/                  # G1 MuJoCo model and demo motions
└── third_party/unitree_sdk2/  # Unitree LCM message types (real-world backend)
```

## Dependencies

Core (MuJoCo online path):

```bash
pip install mujoco imageio imageio-ffmpeg pillow pyyaml
```

Optional:

- `hydra-core` + `omegaconf` — offline replay via `scalebridge/run.py`.
- `torch_tensorrt` — required to load the TensorRT tracking policy and any
  TensorRT planner engine. Install the wheel matching your platform; Linux
  x86_64 and Jetson aarch64 artifacts are not interchangeable.
- `lcm` — real-world backend (Unitree LCM state/command bridge).

No separate installation step is needed for `scalebridge` itself: both entry
points place `deploy/` on `sys.path` at startup.

## Online planning

```bash
python deploy/run_online_generation.py \
  --model_path /path/to/reactivebfm/modelXXXXXXXX.pt \
  --policy_checkpoint /path/to/tracking_policy_tensorrt.pt \
  --text_prompt "walk forward" \
  --planner_device cuda --deploy_device cuda \
  --simulator mujoco_simulator --headless \
  --init_pose A_pose \
  --no-reference_forcing
```

Requirements:

- The planner checkpoint must sit next to its `args.json` (the training
  `save_dir` layout) — train one yourself with the released training recipes
  and data (see the repository README). Normalization statistics
  (`Mean.npy` / `Std.npy`) are part of the dataset directory: they are
  generated by the data preparation pipeline and are included in the released
  data package. Pass `--planner_data_dir`, and `--planner_stats_dataset`
  for composite training datasets.
- The tracking policy must be a TorchScript TensorRT checkpoint with an
  adjacent `*_metadata.json` satisfying
  `input_contract=reactivebfm_qpos_v1` and
  `engine_input_contract=scalebfm_transformer_core_v1` — compile it from the
  official ScaleBFM checkpoint as described in **TensorRT export** below.

Important options: `--future_idx`, `--generation_fps`,
`--reference_blend_frames`, `--async_planner_lookahead_s`,
`--replan_prefix_mode`, `--applied_frame`, `--robot_state_stale_timeout_s`,
`--safe_hold_repeats`, `--record_video`, and `--scalebridge_override PATH=VALUE`
for arbitrary config overrides. `--validate_only` exercises initialization,
planner generation, and tracker warm-up without entering the control loop.

Prompt switching mid-run (see `prompt_scheduler.py`):

- `--prompt_schedule events.json` — scripted `[{time_s, prompt}]` events;
- `--random_prompt_csv captions.csv --random_switch_count N
  --random_switch_interval_s T` — deterministic random switches from a
  caption pool;
- `--interactive_prompts` — type new prompts on stdin while running (user
  input has the highest priority; `--user_prompt_hold_s` shields it from
  scripted/random events);
- `--prompt_clock wall|sim` — clock for scripted/random events.

Use `--simulator real_world` only after MuJoCo validation. The real-world
backend additionally requires the Unitree LCM low-level controller to be
running, and (with `--no-reference_forcing`) a Vive localization client feeding
`scalebridge.utils.vive_tracker.online_client`.

## Offline replay

```bash
cd deploy
python scalebridge/run.py \
  agent.config.control_mode=7 \
  agent.config.checkpoint=/path/to/tracking_policy_tensorrt.pt \
  asset=g1_29dof env=motion_tracking \
  env.config.motion_path=/path/to/motion.npz \
  simulator=mujoco_simulator
```

## Motion playback

`deploy/tools/play_rbfm_npz_mujoco.py` inspects qpos36 motion files in MuJoCo —
both raw clips (NPZ with `qpos`, optional `frequency`/`text`/`quat_order`,
auto-detected) and online session recordings (`motion_buffers.npz` written by
the runner; pick `real_robot_motion36` or `active_plan_motion36` with
`--stream`):

```bash
python deploy/tools/play_rbfm_npz_mujoco.py --input-npz /path/to/motion.npz   # render MP4
python deploy/tools/play_rbfm_npz_mujoco.py --input-npz /path/to/motion_buffers.npz \
  --stream active_plan_motion36                                               # session MP4
python deploy/tools/play_rbfm_npz_mujoco.py --input-npz /path/to/motion.npz \
  --interactive --no-video                                                    # viewer
```

Interactive keys: SPACE pause, R restart, C toggle camera follow.

## TensorRT export

The `scripts/` directory at the repository root provides the compilers that
produce the deployment artifacts.

**Tracking policy (required).** Download the official ScaleBFM pretrained
checkpoint from
[HuggingFace](https://huggingface.co/WeishuaiZeng/ScaleBFM/tree/main/checkpoint)
(`checkpoint/humanoid_transformer_m/model_22200.pt`, ~73 MB; an XL variant is
also available), then compile it **on the deployment machine itself**:

```bash
python scripts/export_scalebfm_tensorrt.py \
  --checkpoint /path/to/model_22200.pt \
  --precision fp32            # or fp16 on the onboard computer
```

The compiler is self-contained: the ScaleBFM network definitions are vendored
under `deploy/third_party/scalebfm/` (credit: [ScaleBFM](https://github.com/zengweishuai/ScaleBFM),
Zeng et al., arXiv:2607.15163), so no external checkout is needed.

This writes `<checkpoint>_tensorrt.pt` plus the adjacent `*_metadata.json`
(`reactivebfm_qpos_v1` contract) required by `BFMAgent`. Pass the compiled
file to `--policy_checkpoint`. `--dry-run` validates the checkpoint
reconstruction on CPU without TensorRT.

**Planner (optional).** `scripts/export_planner_tensorrt.py
--checkpoint modelXXXXXXXX.pt` compiles the ReactiveBFM DiT denoiser for the
`--planner_tensorrt` path.

TensorRT artifacts are platform-specific: compile on the deployment platform
itself — Linux x86_64 and Jetson aarch64 artifacts are not interchangeable.

## Quaternion convention

- **Planner-facing interfaces are xyzw**, matching the ReactiveBFM qpos36 data
  layout (`root_xyz + root_quat_xyzw + 29 DoF`):
  - `MotionTrackingOnlineEnv.set_reference_motion(...)` expects
    `root_pos (T,3)`, `root_quat_xyzw (T,4)`, `dof_pos_policy (T,29)`.
  - `BaseEnv.reset(init_state_dict=...)` accepts `root_quat_xyzw`.
- **ScaleBridge internals are wxyz** (MuJoCo `qpos` order): state buffers,
  simulator state extraction, and the tracking policy all use wxyz.
- The xyzw↔wxyz conversion happens exactly once at these two boundaries and is
  centralized in `scalebridge/utils/quaternion.py`. Do not add ad-hoc
  reorders elsewhere.

Note: the **offline replay** path (`MotionTrackingEnv`,
`scalebridge/data/motion/g1_29dof/squat.npz`) consumes the upstream ScaleBFM
tracking NPZ format (`joint_pos`/`root_pos`/`root_rot` or `body_*_w`, 50 Hz,
**wxyz**) — a file-format contract inherited from ScaleBridge, distinct from
the planner-facing xyzw interfaces above.
